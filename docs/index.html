Un assistant qui écrit une requête, une image ou une boucle ne connaît pas par défaut le référentiel d'écoconception de votre organisation. Une fois le code en production, chaque exécution reproduit ce choix initial chez chaque utilisateur, pendant toute la durée de vie du service. Ce dépôt ferme cet écart : il transforme RGESN, GR491, Opquast et RGAA en instructions que l'assistant charge automatiquement, dans son propre format.

Deux moments, un seul jeu de règles

La règle

Pendant que le code s'écrit

Injectée dans le contexte de l'assistant, elle oriente ce qu'il produit avant même que vous ne le relisiez.

-- demande : « le rapport des opérations d'un client »
SELECT * FROM operations;
SELECT id, client_id, date_operation, montant
FROM operations
WHERE client_id = :id
ORDER BY date_operation DESC
LIMIT 50;

L'agent

Après coup, sur le diff

Relit ce qui a été commité et cite le critère à chaque constat — pour la revue, et pour la montée en compétence de l'équipe.

$ cn review --review-agents eco-check.md

[Moyen] rapport-clients.sql:9
  SELECT * sur une table non filtrée — RGESN 7.x
  → colonnes explicites + pagination

1 constat, 0 régression

Une source, sept assistants

Treize langages, chacun avec ses propres réflexes

Un N+1 ne s'écrit pas pareil en JPA, en Entity Framework ou en ActiveRecord. Chaque règle nomme les motifs spécifiques au langage plutôt que des principes génériques — ce qui se vérifie, se corrige.
